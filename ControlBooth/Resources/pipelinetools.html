ControlBooth Pipeline Tools

A Pipeline runs a chain of executables piped left to right: each stage's stdout feeds the next stage's stdin. ControlBooth automatically appends one stage to the end of every pipeline:

  1. PCMUDPSender — sends the last stage's PCM over UDP to the pipeline's Destination Host / Destination Port (by default AntennaHead's audio-input port, 6019), which streams it to listeners.

So a pipeline's final stage must produce raw signed 16-bit little-endian PCM ("S16LE") at 48000 Hz, 2-channel — the receiver's contract. If your source stage emits anything else (a different rate, mono, a tuner's raw output), add a sox stage to resample; unlike AntennaHead, ControlBooth does not insert one for you.

Conventions

  • Tool names: a bare name (no /) resolves to the bundled helper in Contents/Helpers/ (or a known system tool) when the pipeline starts. ControlBooth is not sandboxed, so a stage may also be an absolute path to any tool installed elsewhere on the system — that is the intended way to use tools ControlBooth doesn't bundle (your own rtl_fm, nrsc5, …).
  • Arguments: one argument per row, passed literally — no shell, no quoting. A flag and its value are two rows (--port, then 6030). Text with spaces is fine in a single row.
  • Use straight dashes: options start with two hyphens (--repeat). If a tool reports an unknown argument that looks right, check for a smart em dash (—) from autocorrect in an older record.
  • --exit-with-parent: most bundled helpers accept this flag (the exceptions are FMDeemphasis, PCMJitterBuffer and LiveAudioRecorder); it makes the helper exit if the app dies unexpectedly, so pipelines never orphan. Recommended on the first stage.

Bundled helpers

PCMSpeechSynth — text-to-speech source

Renders text to speech (S16LE mono at --rate) and writes it to stdout, paced in real time.

OptionDescription
--text <string>Speak this text (one argument row; spaces OK, no quotes needed).
--input stdinRead the text from stdin (to end-of-file).
--input file:<path>Read the text from a file.
--input udp:<port>Wait for text datagrams; each one replaces the current text (send with nc -u).
--rate <hz>Output sample rate, 8000–48000. Default 22050. Mono output — follow with a sox stage to reach 48 kHz stereo.
--voice <id-or-language>Voice identifier or language code (e.g. en-US).
--speech-rate <0..1>Speaking speed. Default: system default.
--ssmlParse the text as SSML markup for prosody control, e.g. <speak>hello <break time="500ms"/> <prosody pitch="+40%">there</prosody></speak>.
--repeatLoop the audio continuously.
--no-paceEmit the rendered audio as fast as the sink accepts instead of metering it in real time — for rendering a fixed clip to a file, not driving a live pipeline. Ignored for the udp source.
--gap <seconds>Silence between repeats. Default 1.0.
--list-voicesPrint available voices and exit.
--exit-with-parentExit if the app dies.

Two routes to prosody control (pitch, pauses, emphasis): the classic voices (identifiers starting com.apple.speech.synthesis.voice. — Fred, Alex, …) honor Apple's embedded speech commands in plain text, e.g. [[pmod 60]], [[pbas 40]], [[slnc 500]], [[rate 120]]. The modern voices (Samantha, Siri) read those aloud instead — use --ssml with them. Don't mix the two syntaxes.

PCMFilePlayer — file/playlist source

Decodes AAC/MP3 (or any format AVAudioFile reads — M4A, WAV, CAF, …) into S16LE PCM at --rate/--channels and writes it to stdout, paced in real time. Every track is decoded into memory before playback starts. Not bundled with ControlBooth — point the stage at an absolute path to a build of it, or use another player that writes raw PCM to stdout.

OptionDescription
--file <path>One track; repeatable, played in the order given.
--playlist <path>A text file listing one path per line (blank lines and # comments ignored); combines with any --file entries in the order the flags appear.
--rate <hz>Output sample rate, 8000–192000. Default 48000.
--channels <n>Output channels, 1–8. Default 2.
--gap <seconds>Silence between tracks, and between the last track and the first when --repeat loops back. Default 0.0.
--repeatLoop the whole playlist continuously.
--exit-with-parentExit if the app dies.

PCMMixer — mix two or more PCM streams

Mixes S16LE inputs sample-wise (with saturation) into one output. All inputs must share the same rate and channel count. Input 0 is the clock master — it paces the output; other inputs are buffered and contribute silence when they under-run, so a stalled source can't freeze the pipeline.

OptionDescription
--input stdin / --input udp:<port>Repeatable; two or more inputs, at most one stdin.
--output udp:<host>:<port>Send output over UDP instead of stdout.
--control-port <n>UDP port for live mix control (see below).
--gain <i>=<g>Initial gain for input i (repeatable; >1 amplifies).
--ratio <0..1>Initial crossfade for inputs 0/1 (gain₀ = 1−r, gain₁ = r).
--exit-with-parentExit if the app dies.

Control commands (one line per UDP datagram, e.g. echo "ratio 0.25" | nc -u -w1 127.0.0.1 6031):

CommandEffect
ratio <0..1>Crossfade inputs 0/1.
gain <i> <g>Set input i's gain.
gainsReply to the sender with the current gain list.

PCMUDPReceiver — UDP → stdout source

Listens for UDP datagrams and writes their payloads to stdout. A convenient bridge for tools you'd rather run outside ControlBooth: start them separately and have them send PCM to a loopback port that this stage reads.

OptionDescription
--port <n>UDP port to listen on. Required.
--bind <addr>Listen address. Default 127.0.0.1 (loopback only); use 0.0.0.0 for LAN senders.
--exit-with-parentExit if the app dies.

PCMUDPSender — stdin → UDP sink

Sends stdin as UDP datagrams (max 2048 bytes each). ControlBooth appends this automatically as every pipeline's final stage, but it can also be used mid-pipeline to feed a PCMMixer input or another machine.

OptionDescription
--port <n>Destination UDP port. Required.
--host <addr>Destination address. Default 127.0.0.1.
--exit-with-parentExit if the app dies.

AudioInputCapture — Core Audio device source

Captures a Core Audio input device (microphone, line-in, loopback drivers) and writes S16LE PCM to stdout.

OptionDescription
--device-name <name>Input device name, e.g. MacBook Pro Microphone. Required.
--rate <hz>Output sample rate. Default 48000.
--channels <n>Output channels. Default 2.
--exit-with-parentExit if the app dies.

AUProcessor — Audio Unit effect stage

Runs stdin → stdout through one installed Audio Unit effect (Apple's built-ins like AUGraphicEQ, AUDynamicsProcessor, AUMatrixReverb, or third-party plugins) — no audio device, no plugin window. Frame counts pass through 1:1, so it slots anywhere a sox effect would. Instead of the plugin's GUI, set parameters with --param, load a .aupreset saved from GarageBand/Logic/AU Lab, or adjust live over the control port.

OptionDescription
--unit <spec>The effect: a name (AUGraphicEQ) or the codes from --list-units (aufx:greq:appl). Required.
--rate <hz>Stream sample rate. Default 48000 — must match the neighboring stages.
--channels <n>Stream channels. Default 2 — must match the neighboring stages.
--param <name>=<value>Set a parameter by its name from --list-params (repeatable; values clamp to the published range). Spaces in names may be written as underscores — Delay_Time=0.4 — which survives any argument splitting.
--preset <path>Load a .aupreset file — the headless route to settings made in the plugin's real GUI.
--factory-preset <index>Select a built-in preset (indexes in --list-params).
--control-port <n>UDP port for live control (see below).
--out-of-processHost the AU in a system extension process — for third-party v2 plugins that won't load in-process.
--list-unitsPrint installed effect units and exit.
--list-paramsPrint the chosen unit's parameters and factory presets, then exit.
--exit-with-parentExit if the app dies.

Control commands (one line per UDP datagram):

CommandEffect
param <name> <value>Set a parameter (the name may contain spaces; the last word is the value).
paramsReply to the sender with all current values.
bypass on|offToggle the effect's bypass.
preset <path>Load a .aupreset file.

PCMPassthrough — no-op stage

Copies stdin to stdout unchanged; takes no options. Useful as a placeholder, and its source is the template for writing new DSP stages.

PCMPrefix — play a clip, then pass stdin through

Plays a pre-rendered raw clip first, then forwards stdin unchanged — the spoken station announcement before live playback. A missing or empty --prefix-file makes it a plain passthrough.

OptionDescription
--prefix-file <path>Raw S16LE clip to play first, at --rate. Must already be at --rate — no resampling is done.
--during-prefix drop|holdWhat to do with stdin while the clip plays: drop it, or hold (buffer) it. Default drop.
--prefix-channels 1|2Channel count of --prefix-file. Default 2; 1 is up-mixed to --channels by sample duplication.
--rate <hz> / --channels <n>Stream format for pacing math. Default 48000 / 2.
--exit-with-parentExit if the app dies.

FMDeemphasis — FM de-emphasis filter

First-order IIR de-emphasis (RC-network model) in floating point, stdin → stdout, format unchanged. Best run at 48 kHz after a sox resample, which keeps it clear of the FM pilot tone and stereo subcarrier. Does not accept --exit-with-parent.

OptionDescription
--rate <hz>Sample rate in Hz. Default 48000.
--channels <n>1 or 2. Default 2.
--tau <µs>De-emphasis time constant in microseconds. Default 75.0 (U.S.); use 50.0 for the European/ITU standard.

PCMJitterBuffer — steady-pace a bursty source

Absorbs bursty upstream delivery (e.g. nrsc5 handing off decoded audio in ~186 ms HD Radio logical-frame blocks) and re-emits the same bytes at a steady real-time pace. Trades a fixed --buffer-ms of latency for that smoothing; no silence is injected on a genuine stall. Place it between the bursty source and the terminal PCMUDPSender. Does not accept --exit-with-parent.

OptionDescription
--rate <hz>Sample rate in Hz. Required. (-r also accepted.)
--channels <n>Channel count. Default 2. (-c also accepted.)
--buffer-ms <ms>Buffer depth in milliseconds — the latency traded for absorbing bursts. Default 400.

LiveAudioRecorder — tee to an MP3/AAC file

A stdin → stdout passthrough (byte-identical) that also encodes the PCM to a file. Can sit anywhere in a chain, or run standalone — several instances at once, one per source. At least one of --mp3 / --aac is required; with neither, it just passes through. Does not accept --exit-with-parent.

OptionDescription
--mp3 <path>Write an MP3 file at this path.
--aac <path>Write an AAC (.m4a) file at this path.
--rate <hz> / --channels <n>Input stream format. Default 48000 / 2.
--mp3-bitrate <kbps>MP3 bitrate in kbps. Default 128.
--aac-bitrate <bps>AAC bitrate in bits per second. Default 128000.
--verboseLog per-chunk encoder progress to stderr.

PCMTranscriber — tee to on-device speech recognition

A stdin → stdout passthrough that also feeds the PCM to Apple's on-device SpeechAnalyzer (macOS 26+; a no-op on older systems). Emits result JSON over UDP and/or appends finalized segments to a transcript file. Needs --udp-port and/or --transcript-file, else there's nothing to do.

OptionDescription
--rate <hz>Input sample rate, 8000–192000. Default 48000.
--channels <n>1 or 2. Default 2.
--locale <bcp47>Recognition locale as a BCP-47 tag. Default en-US.
--udp-port <n>Send newline-delimited JSON transcription events to this port.
--udp-host <addr>Destination for the JSON events. Default 127.0.0.1.
--transcript-file <path>Append finalized segments here (plain text / SRT / VTT by extension).
--partialsAlso emit volatile (not-yet-final) hypotheses over UDP.
--exit-with-parentExit if the app dies.

PCMDistanceGain — distance-based loudness falloff

Spatial-audio prep: attenuates the stream by distance, live-adjustable over a UDP control port. Pairs with PCMBinauralPanner downstream (both take the same distance; a host sends it to both control ports on a change).

OptionDescription
--rate <hz> / --channels <n>Stream format. Default 48000 / 2.
--distance <d>Initial distance in pad units (≥ 0). Default 1.0.
--reference-distance <d>Distance at/inside which gain is unity (> 0). Default 1.0.
--rolloff <r>Falloff exponent. 1.0 = physical inverse-distance; lower is gentler. Default 0.8.
--min-gain <0..1>Gain floor, so a far source fades but never vanishes. Default 0.05.
--control-port <n>UDP port for live distance updates.
--exit-with-parentExit if the app dies.

Control commands (one line per UDP datagram): distance <d>.

PCMBinauralPanner — azimuth/elevation binaural panning

Direction stage: ITD/ILD-based azimuth/elevation panning (not measured HRTF) plus distance-driven air absorption, downmixing to mono and emitting true 2-channel binaural output. Sits downstream of PCMDistanceGain; live-adjustable over its own UDP control port.

OptionDescription
--rate <hz> / --channels <n>Stream format. Default 48000 / 2 (input is downmixed to mono).
--azimuth <deg>Initial azimuth (0 = front, positive = right). Default 0.
--elevation <deg>Initial elevation, −90…90. Default 0.
--head-radius <m>Head radius in metres, for the ITD model. Default 0.0875.
--ild-depth <0..1>Far-ear level reduction at full pan. Default 0.6.
--shadow-min-cutoff <hz>Head-shadow lowpass cutoff at full pan. Default 1500.
--shadow-max-cutoff <hz>Head-shadow lowpass cutoff at azimuth 0 (no shadow). Default 18000.
--elevation-shelf-db <dB>Max high-shelf tilt at ±90° elevation. Default 4.0.
--distance <d>Initial distance in pad units, for air absorption (≥ 0). Default 1.0.
--reference-distance <d>Distance at/inside which there's no air absorption. Match PCMDistanceGain's value. Default 1.0.
--air-absorption-min-cutoff <hz>Lowpass cutoff at --air-absorption-distance. Default 1200.
--air-absorption-max-cutoff <hz>Lowpass cutoff at/inside the reference distance. Default 20000.
--air-absorption-distance <d>Distance at which the cutoff reaches its minimum. Must be greater than --reference-distance. Default 8.0.
--control-port <n>UDP port for live azimuth / elevation / distance updates.
--exit-with-parentExit if the app dies.

Bundled third-party tools

rtl_fm_localradio — RTL-SDR tuner/demodulator

LocalRadio's fork of rtl_fm. Reads the RTL-SDR USB dongle and demodulates to S16LE mono on stdout. Its raw output is at the tuner rate (-s), so it always needs a sox stage after it to reach 48 kHz stereo. Commonly used flags:

FlagDescription
-f <hz>Frequency in Hz. Repeatable for scanning.
-M <mode>Modulation: fm, am, usb, lsb, raw.
-s <hz>Output sample rate — tell the following sox stage this is its input rate.
-g <db>Tuner gain (e.g. 49.6).
-l <level>Squelch level (0 = off).
-o <n>Oversampling.
-F <size> / -A <math>FIR filter size / atan math (std, fast, lut).
-p <ppm>Frequency correction.
-c <port>Send the status feed (frequency, RMS level) as ASCII lines to this UDP port. ControlBooth has no signal meter, so this is only useful if something else you run is listening.
-E <option>Extra options, repeatable (e.g. pad, direct for direct sampling, dc).
-d <index>Dongle selection when more than one is attached.

sox — resampler / filter

General audio processor. For raw-PCM pipeline use, both sides must be described explicitly. The canonical mid-pipeline resample looks like:

sox -V2 -q
    -r <in rate> -e signed-integer -b 16 -c <in ch> -t raw -
    -e signed-integer -b 16 -c <out ch> -t raw -
    rate <out rate> vol 1 dither -s

(each token is one argument row; the two lone - arguments mean stdin/stdout). Effects like vol, deemph, highpass follow at the end. In ControlBooth this is the stage that converts a source's output to the 48 kHz stereo the appended PCMUDPSender expects.

stereodemux — FM stereo decoder

Decodes an FM multiplex (MPX) signal into stereo L/R. Placed right after rtl_fm_localradio: input is rtl_fm's raw output at the tuned rate, -r <rate> tells it that input rate, and it emits 2-channel S16LE (tell the following sox stage its input is 2-channel).

nc — system netcat

macOS's built-in netcat, resolved from /usr/bin/nc. Handy for simple TCP/UDP plumbing, e.g. receiving gqrx's UDP audio: nc with arguments -l, -u, localhost, 7355. For UDP sources, note that nc latches onto the first sender; PCMUDPReceiver is usually the better choice.

Example pipelines

Looping spoken announcement

PCMSpeechSynth emits 22050 Hz mono, so a sox stage resamples to 48 kHz stereo before the appended PCMUDPSender. Two stages:

PCMSpeechSynth  --text | ControlBooth test loop | --repeat | --gap | 5 | --exit-with-parent
sox  -V2 | -q | -r | 22050 | -e | signed-integer | -b | 16 | -c | 1 | -t | raw | - | -e | signed-integer | -b | 16 | -c | 2 | -t | raw | - | rate | 48000

(the | above separates argument rows).

Spoken announcement with an echo effect

The same repeating announcement, run through Apple's AUDelay unit for an echo, then resampled. Three stages:

PCMSpeechSynth  --text | ControlBooth test loop | --repeat | --gap | 5 | --exit-with-parent
AUProcessor  --unit | AUDelay | --rate | 22050 | --channels | 1 | --param | Delay_Time=0.4 | --param | Dry/Wet_Mix=35 | --param | Feedback=40
sox  -V2 | -q | -r | 22050 | -e | signed-integer | -b | 16 | -c | 1 | -t | raw | - | -e | signed-integer | -b | 16 | -c | 2 | -t | raw | - | rate | 48000

The AUProcessor stage's --rate/--channels match the speech stage's output (22050 Hz mono); the sox stage then converts to 48 kHz stereo. A longer Delay Time spaces the echoes out; more Feedback makes them repeat longer; Dry/Wet Mix sets how loud they are (100 = echo only).

External nrsc5 (HD Radio) over the UDP bridge

Run nrsc5 yourself (ControlBooth doesn't bundle it): nrsc5 -o - 89.1 0 | ffmpeg/sox … | PCMUDPSender --port 6030 (or have the tool send UDP itself). Its output is 44100 Hz stereo, so add a sox stage after the receiver. Stages:

PCMUDPReceiver  --port | 6030 | --exit-with-parent
sox  -V2 | -q | -r | 44100 | -e | signed-integer | -b | 16 | -c | 2 | -t | raw | - | -e | signed-integer | -b | 16 | -c | 2 | -t | raw | - | rate | 48000

EQ / compression on any audio stage

Insert between any two stages (here: boosting lows and taming peaks after a device capture, with live control on UDP 6040):

AUProcessor  --unit | AUGraphicEQ | --param | 100.0_Hz=6 | --param | 8000.0_Hz=-3 | --control-port | 6040 | --exit-with-parent

Adjust live: echo "param 100.0 Hz 2" | nc -u -w1 127.0.0.1 6040. Run AUProcessor --list-params --unit AUGraphicEQ in Terminal (inside the app bundle's Contents/Helpers) to see each unit's parameter names.

Radio with a speech ducked underneath

Stage 1 mixes two sources; stdin isn't available in stage 1, so both come in by UDP. Run one pipeline's audio into UDP 6032 and another's speech into UDP 6033 (each ends with PCMUDPSender pointed at that port), then a pipeline whose single stage is:

PCMMixer  --input | udp:6032 | --input | udp:6033 | --control-port | 6031 | --ratio | 0.2 | --exit-with-parent

Adjust the blend live: echo "ratio 0.5" | nc -u -w1 127.0.0.1 6031.

Port picking: a pipeline's Destination Port defaults to 6019 (AntennaHead's audio-input port). For mid-pipeline UDP bridges pick something clear of the 6019–6022 range the AntennaHead/ControlBooth chain uses, and clear of 5000 (AirPlay), 8080/8443 and 8090/8094 (HTTP). Loopback UDP has no backpressure: source stages that generate faster than real time (files, speech) should pace themselves, as PCMSpeechSynth does.
